# Organizer README checklist

Checked against **Instructions for HackAlem AI Participants**, pages 1–2, and the Track 12 brief, English pages 10–12. The organizer asks for an English README with the following eleven items.

| Required item | Where it is covered |
| --- | --- |
| 1. Project name | Akim Lab title |
| 2. Problem and intended users | Introduction and Why we built it |
| 3. Implemented features | What is included and How to play |
| 4. Main user flow | How to play and the replay GIF |
| 5. Technologies, AI models and external services | Run locally and Technical details |
| 6. Components and their interaction | Technical details; full architecture in TECHNICAL.md |
| 7. Setup commands | Run locally: clone, change directory, start |
| 8. Reproducible testing example | Example plan: cost 95 / score 56.54 / zero critical indicators; verified change: cost 100 / score 57.21; test commands |
| 9. Data sources and integrations | Data and limitations; attributed sources in data/README.md |
| 10. Known limits and unimplemented features | How the results work and Data and limitations |
| 11. Deployment link, if available | Explicitly states that no hosted demo is available; local launch is documented |

Track 12 assigns 25 points each to functionality, technical implementation, and README/reproducibility; 15 to value/applicability; and 10 to development potential/originality. This checklist documents coverage, not an awarded score.

The mandatory case flow is covered by the same budget and starting dataset, five decisions across the available categories, budget checks, calculated Astana Quality of Life Score, and AI analysis of benefits and trade-offs. The detailed dataset allows up to two projects per category; it does not require one project in every category. See [acceptance checks](ACCEPTANCE.md).

## Submission is separate

The participant instructions also require pushing the latest code to the platform-provided team repository and selecting **Submit Solution** on the tracks page, with a project name and description. A Git push does not confirm that the platform submission has been made. Nartay completes that step on the event platform.
