# Languages (KZ / RU / EN)

`public/i18n.js` adds a **ҚАЗ · РУС · ENG** switch to the HUD (inside `.hud-nav`; a floating top-right control if the HUD is missing) and translates the rendered UI in place. It is wired with one line in `index.html`:

```html
<script type="module" src="/i18n.js?v=20260923-i18n"></script>
```

- **How it works:** the module matches visible text and the `aria-label`, `title`, `placeholder` and `alt` attributes by their exact English wording. A small set of patterns handles strings with numbers or names, such as `5 choices left to make`, `Q3 / 8 · ILLUSTRATIVE REPLAY` and `Road flow +16`. A MutationObserver re-translates anything that app.js or city.js re-renders.
- **Other files:** app.js, city.js and the shared model keep producing English and need no changes. Scores, numbers and the model are untouched.
- **Unknown text** stays in English. To add a string, append `['English', 'Қазақша', 'Русский']` to `ENTRIES`. If the string carries a number or name, add a pattern to `PATTERNS`.
- **Choosing the language:** the choice is saved in `localStorage` (`akimlab-language`). `?lang=kk|ru|en` forces a language, `<html lang>` and the document title follow it, and a `akimlab:language` event fires on `window` with `{ detail: { language } }`.
- **Opting out:** put `data-i18n-skip` or `translate="no"` on an element to keep it from being translated.
- **Not translated yet:** AI adviser answers and the voice-over come from the server in English. A later step could send the language with those requests.
